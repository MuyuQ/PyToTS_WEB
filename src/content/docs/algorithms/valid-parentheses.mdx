## 问题描述

给定一个只包含字符 `'('`、`')'`、`'{'`、`'}'`、`'['`、`']'` 的字符串 `s`，判断该字符串是否有效。有效需同时满足：左括号必须由同类型右括号闭合，闭合顺序必须正确（后开先合）。

**示例 1**

```text
输入：s = "()[]{}"
输出：true
解释：三种括号各自依次闭合，顺序正确
```

**示例 2**

```text
输入：s = "([)]"
输出：false
解释：圆括号与方括号交叉闭合，顺序错误
```

**约束条件**

- `1 <= s.length <= 10⁴`
- `s` 仅由六种括号字符组成

**边界情况**：空字符串按有效处理（无未闭合括号）；单个右括号如 `")"` 因栈空无法匹配而无效；奇数长度字符串必然存在未闭合括号，可作为提前剪枝但非必需；遍历结束时栈非空（如 `"((("`）同样无效，结尾判空不可省略。

## 暴力解与瓶颈

朴素思路是反复删除相邻合法对 `"()"`、`"{}"`、`"[]"`，直到删不动为止：

```python
def is_valid_brute(s: str) -> bool:
    prev = None
    while prev != s:
        prev = s
        s = s.replace("()", "").replace("{}", "").replace("[]", "")
    return s == ""
```

该写法语义直观，但瓶颈明显：每次 `replace` 都扫描整个字符串，最坏需要 O(n) 轮（如 `"((...))"` 逐层剥离），总时间 O(n²)，且反复构造新字符串带来额外内存开销。优化方向是单遍扫描配合显式状态：用栈记住"尚未闭合的左括号"，把内层匹配转化为栈顶比较，消除重复扫描。

## 思路分析

栈的后进先出特性恰好对应括号的后开先合。用映射表记录右括号到左括号的期望关系。遍历字符：左括号直接入栈等待闭合；右括号则检查栈顶是否匹配，匹配即弹出，不匹配（含栈空）即失败。遍历结束时栈空才算完全闭合。

以 `s = "{[]}"` 为例：

| 步骤 | 字符 | 栈变化前 | 动作             | 栈变化后 |
| ---- | ---- | -------- | ---------------- | -------- |
| 1    | `{`  | `[]`     | 左括号，入栈     | `['{']`  |
| 2    | `[`  | `['{']`  | 左括号，入栈     | `['{','[']` |
| 3    | `]`  | `['{','[']` | 右括号，栈顶匹配，弹出 | `['{']` |
| 4    | `}`  | `['{']`  | 右括号，栈顶匹配，弹出 | `[]`     |

结束时栈空，返回有效。再看 `s = "([)]"` 在第 3 步即失败：读到 `')'` 时栈顶为 `'['`，与期望 `'('` 不符。

:::tip
关键细节是右括号分支必须同时检查两个条件：栈非空且栈顶等于映射值。顺序不可颠倒，先判空再取栈顶，否则空栈取顶直接越界；映射方向固定为右括号到左括号，避免正反两张表。
:::

## 复杂度分析

| 解法         | 时间复杂度 | 空间复杂度 | 说明                           |
| ------------ | ---------- | ---------- | ------------------------------ |
| 反复删除相邻对 | O(n²)     | O(n)       | 多轮扫描字符串，反复分配新串   |
| 栈单遍扫描   | O(n)       | O(n)       | 每个字符入栈出栈各至多一次     |

栈解法每个字符最多入栈一次、出栈一次，均摊 O(1)，总时间线性。空间最坏 O(n)（如全是左括号），属于为正确表达嵌套深度必须付出的代价。

## 双语实现

  <TabItem label="Python" icon="seti:python">
    ```python
    # 有效的括号 - Python 实现
    # 时间复杂度: O(n), 空间复杂度: O(n)
    # 核心思路: 栈匹配，左括号入栈，右括号验栈顶
    def is_valid(s: str) -> bool:
        # 栈存放尚未闭合的左括号
        stack: list[str] = []

        # 右括号到左括号的映射，右括号分支查表
        mapping: dict[str, str] = {")": "(", "}": "{", "]": "["}

        # 单遍扫描每个字符
        for char in s:
            # 右括号分支：需要与栈顶匹配
            if char in mapping:
                # 栈空或栈顶类型不符即无效
                if not stack or stack[-1] != mapping[char]:
                    return False
                # 匹配成功，弹出栈顶
                stack.pop()
            else:
                # 左括号分支：入栈等待闭合
                stack.append(char)

        # 栈空说明全部正确闭合
        return len(stack) == 0

    # 测试用例
    print(is_valid("()"))  # True
    print(is_valid("()[]{}"))  # True
    print(is_valid("(]"))  # False
    print(is_valid("([)]"))  # False
    ```

    ```typescript
    // 有效的括号 - TypeScript 实现
    // 时间复杂度: O(n), 空间复杂度: O(n)
    // 核心思路: 栈匹配，左括号入栈，右括号验栈顶
    function isValid(s: string): boolean {
      // 栈存放尚未闭合的左括号，数组模拟栈
      const stack: string[] = [];

      // 右括号到左括号的映射，右括号分支查表
      const mapping: Record<string, string> = { ")": "(", "}": "{", "]": "[" };

      // 单遍扫描每个字符，for...of 直接取值
      for (const char of s) {
        // 右括号分支：需要与栈顶匹配
        if (char in mapping) {
          // 栈空或栈顶类型不符即无效
          if (stack.length === 0 || stack[stack.length - 1] !== mapping[char]) {
            return false;
          }
          // 匹配成功，弹出栈顶
          stack.pop();
        } else {
          // 左括号分支：入栈等待闭合
          stack.push(char);
        }
      }

      // 栈空说明全部正确闭合
      return stack.length === 0;
    }

    // 测试用例
    console.log(isValid("()")); // true
    console.log(isValid("()[]{}")); // true
    console.log(isValid("(]")); // false
    console.log(isValid("([)]")); // false
    ```

## Python 与 TypeScript 差异点评

逻辑完全同构，差异在于栈顶访问与映射查表的表达：

```python
# 栈顶访问：负索引直接取顶
if not stack or stack[-1] != mapping[char]:
    return False
```

```typescript
// 栈顶访问：length - 1 显式取顶
if (stack.length === 0 || stack[stack.length - 1] !== mapping[char]) {
  return false;
}
```

| 关注点   | Python                                         | TypeScript                                                        |
| -------- | ---------------------------------------------- | ----------------------------------------------------------------- |
| 栈实现   | `list` 兼作栈，`append` / `pop`                | `string[]` 兼作栈，`push` / `pop`，类型参数显式                   |
| 栈顶读取 | `stack[-1]`，负索引简洁                        | `stack[stack.length - 1]`，需显式计算                             |
| 空栈判断 | `not stack` 判空                               | `stack.length === 0` 判空                                        |
| 映射结构 | `dict[str, str]`                               | `Record<string, string>`，键值类型显式                            |
| 成员检查 | `char in mapping` 查键                         | `char in mapping` 同样查键，心智一致                              |
| 取值类型 | `mapping[char]` 命中即 `str`                   | `mapping[char]` 为 `string`，配合 `in` 收窄后使用                 |
| 输出测试 | `print(...)` 输出 `True` / `False`             | `console.log(...)` 输出 `true` / `false`                          |

:::note
TypeScript 用 `in` 检查 `Record` 时，原型链属性（如 `"toString"`）理论上也会命中。本题输入限定为六种括号，无实际影响；若输入开放，应改用 `Map` 或 `Object.hasOwn` 以避免原型污染类误判。
:::

## 常见错误分析

### 1. 未判空直接取栈顶，右括号开头即崩溃

```python
# 错误：栈空时 stack[-1] 越界
if stack[-1] != mapping[char]:
    return False
```

输入 `s = ")"` 时栈为空，取栈顶直接抛 `IndexError`。**改法**：固定模板 `if not stack or stack[-1] != mapping[char]`，短路求值保证先判空。

### 2. 只比较类型不比较顺序，误判交叉闭合

```python
# 错误：只统计数量，不检查顺序
return s.count("(") == s.count(")") and s.count("[") == s.count("]")
```

该写法对 `"([)]"` 返回有效，但交叉闭合违反后开先合。**改法**：凡涉及嵌套顺序必须用栈，计数器只能处理单一种类括号。

### 3. TypeScript 里 `pop()` 返回值类型处理不当

```typescript
// 错误：strict 下 pop() 返回 string | undefined
const top: string = stack.pop();
if (top !== mapping[char]) {
  return false;
}
```

`strict` 模式下 `pop()` 可能返回 `undefined`（空栈弹出），直接赋给 `string` 编译不通过；即使断言绕过，语义上也把"弹出"与"检查"混在一起。**改法**：保持正解的先读栈顶、再 `pop()` 结构，`pop()` 返回值直接丢弃，不引入多余的联合类型。

## 面试变体

1. **忽略非括号字符**：输入混入字母或空格时跳过非括号字符，括号逻辑不变。扫描时先判断字符是否属于六种括号之一即可，复杂度仍为时间 O(n)、空间 O(n)。
2. **最少添加使有效**：允许插入括号，求最少插入数使字符串有效。栈思路延续：右括号失配时计数加一（视为补左括号），结束时栈大小即未闭合左括号数，两者相加为答案。时间 O(n)、空间 O(n)，也可用计数器优化到 O(1)。
3. **最长有效括号子串**：给定仅含 `'('`、`')'` 的字符串，求最长有效子串长度。栈内存放"未匹配下标"而非字符，以下标差计算长度，需额外维护基准位置。时间 O(n)、空间 O(n)。滑窗类子串问题可对照[无重复字符的最长子串](../longest-substring-without-repeating/)体会下标管理的异同。
4. **多组嵌套深度校验**：除有效性外再求最大嵌套深度。栈逻辑不变，入栈时用 `len(stack)` 更新最大值即可，复杂度不变，时间 O(n)、空间 O(n)。

## 面试追问

- 为什么右括号到左括号的单向映射就够用？（左括号分支无需查表，直接入栈；右括号分支只需知道期望的栈顶类型，单张表足以表达全部约束。）
- 栈的最坏空间能否优化到 O(1)？（仅两种括号且只判有效时可用计数器；三种类别混杂且要求顺序时，嵌套种类信息必须保留，O(n) 空间不可省。）
- `in` 检查字典与集合的平均复杂度是多少？（平均 O(1)，依赖哈希；本题映射仅 3 项，常数可忽略，重点在于单遍扫描带来的线性总时间。）
- 遍历结束为何还要判空？（右括号分支只保证"已出现的右括号都匹配"，左括号过剩如 `"((("` 全程不触发失败分支，只能由结尾 `len(stack) == 0` 捕获。）
