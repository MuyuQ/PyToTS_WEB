## 问题描述

给定一个长度为 `n` 的整数数组 `height`。有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])`。找出其中的两条线，使得它们与 x 轴共同构成的容器可以容纳最多的水。返回最大水量。

**示例 1**

```text
输入：height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
输出：49
解释：索引 1 与 8 的线构成容器，宽 7、高 7，面积 49。
```

**示例 2**

```text
输入：height = [1, 1]
输出：1
解释：只有一对线，宽 1、高 1。
```

**约束条件**

- `n == height.length`
- `2 <= n <= 10⁵`
- `0 <= height[i] <= 10⁴`

**边界情况**：`n = 2` 只有一种选择；高度为 0 的线不能作为有效边；递减数组最优在两端，递增数组同样先看两端；等高时移动哪边都不影响正确性。

## 暴力解与瓶颈

朴素想法是枚举所有线对并取最大面积：

```python
def max_area_brute(height: list[int]) -> int:
    best = 0
    n = len(height)
    for i in range(n):
        for j in range(i + 1, n):
            area = (j - i) * min(height[i], height[j])
            best = max(best, area)
    return best
```

双循环 O(n²)，`n = 10⁵` 时完全不可行。瓶颈在于**重复计算了大量不可能更优的组合**：宽度在缩小，若高度也不增加，面积必然变小。优化方向是贪心双指针：从最宽的两端出发，每次舍弃短板一侧，因为保留短板只会让宽度白白缩小。

## 思路分析

最优解用左右指针夹逼。面积由 `width * min(左右高度)` 决定；移动高的一侧，宽度减小而高度受短板限制不增，面积必减；只有移动短的一侧，才可能遇到更高的线。

以 `height = [1, 8, 6, 2, 5, 4, 8, 3, 7]` 为例：

| 步骤 | `left` | `right` | 宽 × 高 | 面积 | 移动               |
| ---- | ------ | ------- | ------- | ---- | ------------------ |
| 1    | 0(1)   | 8(7)    | `8 × 1` | 8    | 左短，`left` 右移  |
| 2    | 1(8)   | 8(7)    | `7 × 7` | 49   | 右短，`right` 左移 |
| 3    | 1(8)   | 7(3)    | `6 × 3` | 18   | 右短，`right` 左移 |
| 4    | 1(8)   | 6(8)    | `5 × 8` | 40   | 相等，移动右指针   |

:::tip
关键细节是移动条件 `height[left] < height[right]` 时移左，否则移右：等高时移哪边均可，面积公式始终用 `min` 取短板，更新用 `max` 保留最优。
:::

## 复杂度分析

| 解法       | 时间复杂度 | 空间复杂度 | 说明                      |
| ---------- | ---------- | ---------- | ------------------------- |
| 双循环枚举 | O(n²)      | O(1)       | 枚举所有线对，n 大时超时  |
| 双指针贪心 | O(n)       | O(1)       | 指针共移动 n 次，常数空间 |

## 双语实现

<Tabs syncKey="language">
  <TabItem label="Python" icon="seti:python">
    ```python
    # 盛最多水的容器 - Python 实现（双指针贪心）
    # 时间复杂度: O(n), 空间复杂度: O(1)
    # 核心思路: 从两端出发，每次移动短板一侧
    def max_area(height: list[int]) -> int:
        left, right = 0, len(height) - 1
        max_water = 0

        # 指针相遇前持续夹逼
        while left < right:
            width = right - left
            # 木桶效应：高度由短板决定
            current_height = min(height[left], height[right])
            current_area = width * current_height
            max_water = max(max_water, current_area)

            # 移动短板，保留长板才可能变优
            if height[left] < height[right]:
                left += 1
            else:
                right -= 1

        return max_water

    # 测试用例
    print(max_area([1, 8, 6, 2, 5, 4, 8, 3, 7]))  # 49
    print(max_area([1, 1]))  # 1
    print(max_area([4, 3, 2, 1, 4]))  # 16
    ```

    // 盛最多水的容器 - TypeScript 实现（双指针贪心）
    // 时间复杂度: O(n), 空间复杂度: O(1)

          left++;
        } else {
          right--;
        }
      }

      return maxWater;
    }

    console.log(maxArea([1, 1])); // 1

## Python 与 TypeScript 差异点评

指针流程完全一致，差异在数学函数与变量声明上：

```python
# 内置函数直接可用
current_height = min(height[left], height[right])
max_water = max(max_water, current_area)
```

```typescript
// 数学函数挂在 Math 下
const currentHeight = Math.min(height[left], height[right]);
maxWater = Math.max(maxWater, currentArea);
```

| 关注点   | Python                            | TypeScript                               |
| -------- | --------------------------------- | ---------------------------------------- |
| 取最小   | `min(a, b)` 内置                  | `Math.min(a, b)`，需加 `Math.` 前缀      |
| 取最大   | `max(a, b)` 内置                  | `Math.max(a, b)`                         |
| 指针声明 | `left, right = 0, len-1` 元组解包 | `let left` / `let right`，指针需可变绑定 |
| 最优值   | `max_water = 0`                   | `let maxWater = 0`，小驼峰命名           |
| 数组长度 | `len(height)`                     | `height.length` 属性                     |
| 输出测试 | `print(...)`                      | `console.log(...)`                       |

:::note
`left`、`right`、`maxWater` 必须用 `let` 而非 `const`，指针与最优值都会被反复赋值。从 Python 迁移时注意命名同步改为小驼峰，但下标语义保持一致。
:::

## 常见错误分析

### 1. 高度取 `max` 而非 `min`

```python
# 错误：容器会漏水，高度由短板决定
current_area = width * max(height[left], height[right])
```

`[1, 8]` 会被算成面积 8，实际只能盛 1。**改法**：高度一律 `min`，对应 TS 的 `Math.min`。

### 2. 移动长板一侧

```python
# 错误：舍弃了可能的最优边
if height[left] < height[right]:
    right -= 1
else:
    left += 1
```

移动高侧后宽度减小、高度不增，面积必减，最优解可能被跳过。**改法**：短板侧移动，长板侧保留。

### 3. TypeScript 里误用 `const` 声明指针

```typescript
// 错误：strict 下重复赋值编译不通过
const left = 0;
left++; // Cannot assign to 'left' because it is a constant
```

指针与最优值都会变化。**改法**：三者统一用 `let`。Python 无 `const` 概念，`left += 1` 自然合法，迁移时需补上可变性声明。

## 面试变体

1. **接雨水（进阶）**：同样是高度数组，但求整体蓄水量，需左右最大值预处理或双指针变体。时间 O(n)、空间 O(1)，短板思想升级为两侧最大值比较。
2. **最接近目标面积**：给定目标值找最接近的线对，双指针框架不变，只是更新条件改为差值比较。时间 O(n)、空间 O(1)。
3. **有序两数之和的指针思想**：同样从两端夹逼、按比较结果移动一侧（详见[两数之和](../two-sum/)与[三数之和](../3sum/)）。容器题移短板，和问题移大小侧，心智可互相迁移。

## 面试追问

- 为什么移动短板一定不漏最优？（短板固定的所有更窄组合高度不增、宽度递减，答案要点是排除法的完备性。）
- 等高时移动哪边？（任选一边，另一边的全部更窄组合同样可被排除。）
- 暴力为何是 O(n²)？（线对数量为 C(n, 2)，n 增大时平方增长。）
- 高度含 0 会 neighbourhood 破坏逻辑吗？（不会，0 只会让面积为 0 并触发短板移动，流程不变。）
