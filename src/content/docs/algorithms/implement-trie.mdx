## 问题描述

实现 Trie（前缀树），支持 `insert`、`search`、`startsWith` 三个操作：

- `insert(word)`：向 Trie 中插入字符串 `word`
- `search(word)`：`word` 在 Trie 中完整出现过则返回 `true`，否则返回 `false`
- `startsWith(prefix)`：之前插入的字符串中有以 `prefix` 为前缀的则返回 `true`，否则返回 `false`

**示例 1**

```text
输入：
Trie trie = new Trie();
trie.insert("apple");
trie.search("apple");    // 返回 true
trie.search("app");      // 返回 false
trie.startsWith("app");  // 返回 true
输出：[true, false, true]
解释：只有完整插入过的单词才能被 search 命中，前缀命中走 startsWith。
```

**示例 2**

```text
输入：
trie.insert("app");
trie.search("app");      // 返回 true
trie.startsWith("ap");   // 返回 true
trie.search("ap");       // 返回 false
输出：[true, true, false]
解释：插入 "app" 后，"ap" 只是路径存在，不是完整单词。
```

**约束条件**

- `1 <= word.length, prefix.length <= 2000`
- `word` 和 `prefix` 仅由小写英文字母组成
- `insert`、`search`、`startsWith` 的调用总数不超过 `3 * 10^4` 次
- 插入的单词不会重复插入相同完整单词以外的特殊处理，结果保持幂等

**边界情况**：空 Trie 上查询直接返回 `false`；`search` 必须同时满足路径存在与结尾标记，`startsWith` 只要求路径存在；重复插入同一单词不改变结构，只重复标记结尾。

## 暴力解与瓶颈

朴素解法是用集合存下所有插入过的单词，查询时直接查集合或扫描前缀：

```python
class NaiveTrie:
    def __init__(self) -> None:
        self.words: set[str] = set()

    def insert(self, word: str) -> None:
        self.words.add(word)

    def search(self, word: str) -> bool:
        return word in self.words

    def startsWith(self, prefix: str) -> bool:
        return any(w.startswith(prefix) for w in self.words)
```

它的瓶颈在 `startsWith`：每次都要遍历全部单词并逐字符比较前缀，最坏时间 O(N \* m)，N 为单词数，m 为前缀长度。当单词量大且前缀查询频繁时，扫描成为瓶颈。优化方向是把公共前缀只存一次，用树形结构共享路径，让每次查询只走 `len(prefix)` 步。

## 思路分析

最优解是标准 Trie：每个节点保存子节点映射 `children` 与结尾标记 `is_end`。根节点表示空串，从根出发的一条路径表示一个前缀。

- `insert(word)`：从根开始逐字符下走，缺失则新建节点，走完后标记 `is_end = True`
- `search(word)`：走完整个 `word` 且落点 `is_end` 为真才返回真
- `startsWith(prefix)`：能走完整个 `prefix` 即返回真，不检查结尾

以空 Trie 依次插入 `"apple"` 再插入 `"app"`，第二次插入的干跑过程如下：

| 步骤 | `char` | 查表前动作     | 结果                                   |
| ---- | ------ | -------------- | -------------------------------------- |
| 1    | `a`    | 根已有 `a`     | 下走到 `a`                             |
| 2    | `p`    | `a` 已有 `p`   | 下走到 `p`                             |
| 3    | `p`    | 已有第二层 `p` | 下走到 `p`，标记该节点 `is_end = True` |

此时 `"app"` 节点与 `"apple"` 路径上的节点是同一个对象，只是多了一个结尾标记。`search("app")` 因此由假变真，而 `startsWith("ap")` 在插入前后一直为真。

:::tip
关键细节是区分路径存在与单词结尾：`search` 必须检查 `is_end`，`startsWith` 不检查。插入 `"apple"` 后 `search("app")` 为假，正是因为中间节点缺少结尾标记。
:::

## 复杂度分析

| 解法        | 时间复杂度                                           | 空间复杂度  | 说明                                |
| ----------- | ---------------------------------------------------- | ----------- | ----------------------------------- |
| 暴力集合    | `insert` O(1)，`search` O(1)，`startsWith` O(N \* m) | O(总字符数) | 前缀查询每次全量扫描                |
| Trie 最优解 | `insert`/`search`/`startsWith` 均为 O(m)             | O(总字符数) | 公共前缀只存一次，查询只走 key 长度 |

    ```python
    # 实现 Trie - Python 实现，insert/search/startsWith 均为 O(m)
    # 核心思路: 共享前缀，children 存边，is_end 区分单词与前缀
    class TrieNode:
        def __init__(self) -> None:
            self.children: dict[str, TrieNode] = {}
            self.is_end = False

    class Trie:
        def __init__(self) -> None:
            self.root = TrieNode()

        def insert(self, word: str) -> None:
            node = self.root
            for char in word:
                if char not in node.children:
                    node.children[char] = TrieNode()
                node = node.children[char]
            node.is_end = True

        def search(self, word: str) -> bool:
            node = self._find_node(word)
            return node is not None and node.is_end

        def startsWith(self, prefix: str) -> bool:
            return self._find_node(prefix) is not None

        def _find_node(self, prefix: str):
            node = self.root
            for char in prefix:
                if char not in node.children:
                    return None
                node = node.children[char]
            return node

    # 测试用例
    trie = Trie()
    trie.insert("apple")
    print(trie.search("apple"))  # True
    print(trie.search("app"))  # False
    print(trie.startsWith("app"))  # True
    trie.insert("app")
    print(trie.search("app"))  # True
    print(trie.startsWith("ap"))  # True
    print(trie.search("ap"))  # False
    ```

    ```typescript
    // 实现 Trie - TypeScript 实现，insert/search/startsWith 均为 O(m)
    // 核心思路: 共享前缀，children 存边，isEnd 区分单词与前缀
    class TrieNode {
      children: Map<string, TrieNode>;
      isEnd: boolean;

      constructor() {
        this.children = new Map();
        this.isEnd = false;
      }
    }

    class Trie {
      private root: TrieNode;

      constructor() {
        this.root = new TrieNode();
      }

      insert(word: string): void {
        let node = this.root;
        for (const char of word) {
          if (!node.children.has(char)) {
            node.children.set(char, new TrieNode());
          }
          node = node.children.get(char)!;
        }
        node.isEnd = true;
      }

      search(word: string): boolean {
        // 必须路径存在且是单词结尾
        const node = this.findNode(word);
        return node !== null && node.isEnd;
      }

      startsWith(prefix: string): boolean {
        // 路径存在即命中
        return this.findNode(prefix) !== null;
      }

      private findNode(prefix: string): TrieNode | null {
        let node = this.root;
        for (const char of prefix) {
          const child = node.children.get(char);
          if (child === undefined) {
            return null;
          }
          node = child;
        }
        return node;
      }
    }

    // 测试用例
    const trie = new Trie();
    trie.insert("apple");
    console.log(trie.search("apple")); // true
    console.log(trie.search("app")); // false
    console.log(trie.startsWith("app")); // true
    trie.insert("app");
    console.log(trie.search("app")); // true
    console.log(trie.startsWith("ap")); // true
    console.log(trie.search("ap")); // false
    ```

## Python 与 TypeScript 差异点评

| 关注点     | Python                                   | TypeScript                                                                |
| ---------- | ---------------------------------------- | ------------------------------------------------------------------------- |
| 子节点容器 | `dict[str, TrieNode]`，字面量即可        | `Map<string, TrieNode>`，泛型写清键值类型                                 |
| 缺边检查   | `char not in node.children`              | `!node.children.has(char)`                                                |
| 取子节点   | `node.children[char]`，缺席抛 `KeyError` | `node.children.get(char)` 返回 `TrieNode \| undefined`，命中后用 `!` 断言 |
| 辅助方法   | `_find_node`，单下划线表示内部使用       | `private findNode`，访问修饰符强制封装                                    |
| 命名风格   | `is_end`、`_find_node` 蛇形              | `isEnd`、`findNode` 驼峰                                                  |
| 空值       | `None`                                   | `null`，配合 `undefined` 区分缺席                                         |

:::note
`node.children.get(char)!` 的 `!` 是非空断言，前提是上一行 `has` 或 `child === undefined` 检查已经确认存在。不要在没有依据的位置使用 `!`，更稳妥的写法是像 `findNode` 那样用局部变量 `child` 收窄。
:::

## 常见错误分析

### 1. 插入后忘记标记结尾

```python
# 错误：走完路径但没有标记
node = node.children[char]
# 缺少 node.is_end = True
```

`search` 依赖 `is_end` 区分单词与前缀，缺少标记会导致插入后依然查不到。**改法**：`insert` 末尾固定写 `node.is_end = True`。

### 2. `search` 复用了 `startsWith` 的逻辑

```python
# 错误：只判断路径存在
def search(self, word: str) -> bool:
    return self._find_node(word) is not None
```

插入 `"apple"` 后 `search("app")` 会误报 `True`。**改法**：追加 `and node.is_end`，只有结尾标记才能算单词命中。

### 3. TypeScript 里忽略 `Map.get` 的 `undefined`

```typescript
// 错误：strict 模式下编译不通过
node = node.children.get(char); // TrieNode | undefined 不能赋给 TrieNode
```

`Map.get` 的返回类型永远带 `undefined`。**改法**：先 `has` 检查再 `get(char)!` 断言，或用 `const child = get(...)`判空后赋值，Python 侧对应问题是直接下标访问缺席键会抛 `KeyError`，需要先做成员检查。

## 面试变体

1. **实现删除**：支持 `erase(word)` 删除一个单词。只清除结尾标记不够，还要自底向上回收不再被共享的节点。时间 O(m)，空间 O(1) 额外开销，难点是判断何时停止回收。
2. **前缀计数**：每个节点额外存 `count` 表示经过该节点的单词数，`startsWith` 升级为返回个数。写入时沿路加一，时间仍为 O(m)。
3. **自动补全**：给定前缀返回全部补全结果。先定位到前缀节点，再对子树做 DFS 收集，时间 O(p + k)，p 为前缀长，k 为输出总长度。
4. **单词搜索 II**：在字符矩阵中找字典里出现过的全部单词（详见[单词搜索](../word-search/)）。把字典建成 Trie 后在矩阵上做 DFS，剪枝掉无前缀分支，总复杂度远小于每个单词单独搜索。
5. **设计题串联**：Trie 属于典型设计类题目，可对比[最近最少使用缓存](../lru-cache/)的哈希加链表设计，体会空间换时间的通用思路。

## 面试追问

- 为什么不用哈希表存所有前缀？（前缀总数是字符总数的平方级展开，Trie 把公共前缀合并，查询同样 O(m) 但空间更省。）
- `search` 与 `startsWith` 的区别在实现上只有一行，背后语义是什么？（路径存在表示前缀成立，结尾标记表示单词成立，插入 `"apple"` 与 `"app"` 共享路径但结尾不同。）
- 字符集很大（如 Unicode）时如何控制内存？（子节点改用排序数组或压缩边的基数树，用查询时间换空间，或按需建边。）
- 如何支持通配符搜索（如 `.` 匹配任意字符）？（遇到通配符时对当前节点全部子节点做 DFS，时间退化到 O(分支数 ^ 通配符数)。）
