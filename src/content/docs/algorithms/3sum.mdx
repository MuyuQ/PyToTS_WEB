## 问题描述

给你一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足下标互不相同且和为 0。请返回所有和为 0 且不重复的三元组。

**示例 1**

```text
输入：nums = [-1, 0, 1, 2, -1, -4]
输出：[[-1, -1, 2], [-1, 0, 1]]
解释：-1 + -1 + 2 = 0，-1 + 0 + 1 = 0。
```

**示例 2**

```text
输入：nums = [0, 1, 1]
输出：[]
解释：不存在和为 0 的三元组。
```

**约束条件**

- `3 <= nums.length <= 3000`
- `-10⁵ <= nums[i] <= 10⁵`
- 答案去重：`[1, -1, 0]` 与 `[-1, 1, 0]` 视为同一答案

**边界情况**：全零数组答案唯一 `[[0, 0, 0]]`；长度不足 3 直接返回空；大量重复元素时去重逻辑决定正确性；无解返回空数组而非 `null`。

## 暴力解与瓶颈

最直接的想法是三层循环枚举所有三元组：

```python
def three_sum_brute(nums: list[int]) -> list[list[int]]:
    n = len(nums)
    seen: set[tuple[int, int, int]] = set()
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                if nums[i] + nums[j] + nums[k] == 0:
                    seen.add(tuple(sorted([nums[i], nums[j], nums[k]])))
    return [list(t) for t in seen]
```

三层循环 O(n³)，`n = 3000` 时不可接受，且去重依赖排序加集合，常数很大。瓶颈在于**内两层只是在查找两数之和**，却用了 O(n²) 枚举。优化方向是排序后固定第一个数，剩余部分退化为有序两数之和，用双指针 O(n) 解决，总复杂度降到 O(n²)。

## 思路分析

最优解先排序，再固定 `nums[i]`，用 `left = i + 1`、`right = n - 1` 双指针逼近 `target = -nums[i]`。和太小则 `left` 右移，和太大则 `right` 左移，命中则收集并跳过重复值。

以排序后 `[-4, -1, -1, 0, 1, 2]`、固定 `i = 1`（值为 -1）为例：

| 步骤 | `left` | `right` | `left+right` 与 `target=1` 比较 | 动作                         |
| ---- | ------ | ------- | ------------------------------- | ---------------------------- |
| 1    | 2(-1)  | 5(2)    | `1 == 1`                        | 收集 `[-1,-1,2]`，双指针内移 |
| 2    | 3(0)   | 4(1)    | `1 == 1`                        | 收集 `[-1,0,1]`，双指针内移  |
| 3    | 4      | 3       | `left >= right`                 | 本轮结束                     |

:::tip
关键细节有三处：外层跳过 `nums[i] == nums[i-1]`；命中后 `left`、`right` 分别跳过连续重复值；命中后双指针必须同时移动，否则陷入死循环或重复收集。
:::

## 复杂度分析

| 解法         | 时间复杂度 | 空间复杂度 | 说明                              |
| ------------ | ---------- | ---------- | --------------------------------- |
| 三层暴力枚举 | O(n³)      | O(n)       | 枚举全部三元组，集合去重          |
| 排序加双指针 | O(n²)      | O(1)       | 排序 O(n log n)，双指针主导 O(n²) |

<Tabs syncKey="language">
  <TabItem label="Python" icon="seti:python">
    ```python
    # 三数之和 - Python 实现（排序 + 双指针）
    # 时间复杂度: O(n^2), 空间复杂度: O(1) 不计输出
    # 核心思路: 固定第一个数，双指针找和为 -nums[i] 的两数
    def three_sum(nums: list[int]) -> list[list[int]]:
        nums.sort()
        result: list[list[int]] = []
        n = len(nums)

        # 至少留两个位置给 left 和 right
        for i in range(n - 2):
            # 去重：跳过相同的第一个数
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            # 剪枝：最小数已大于 0，后面不可能凑出 0
            if nums[i] > 0:
                break

            left, right = i + 1, n - 1
            target = -nums[i]

            while left < right:
                current_sum = nums[left] + nums[right]
                if current_sum == target:
                    result.append([nums[i], nums[left], nums[right]])
                    # 跳过相同的第二个数和第三个数
                    while left < right and nums[left] == nums[left + 1]:
                        left += 1
                    while left < right and nums[right] == nums[right - 1]:
                        right -= 1
                    # 双指针同时内移
                    left += 1
                    right -= 1
                elif current_sum < target:
                    left += 1
                else:
                    right -= 1

        return result

    # 测试用例
    print(three_sum([-1, 0, 1, 2, -1, -4]))  # [[-1, -1, 2], [-1, 0, 1]]
    print(three_sum([0, 1, 1]))  # []
    print(three_sum([0, 0, 0]))  # [[0, 0, 0]]
    ```

    // 三数之和 - TypeScript 实现（排序 + 双指针）
    // 时间复杂度: O(n^2), 空间复杂度: O(1) 不计输出
    // 核心思路: 固定第一个数，双指针找和为 -nums[i] 的两数
    function threeSum(nums: number[]): number[][] {
      nums.sort((a, b) => a - b);
      const result: number[][] = [];
      const n = nums.length;

      // 至少留两个位置给 left 和 right
      for (let i = 0; i < n - 2; i++) {
        // 去重：跳过相同的第一个数
        if (i > 0 && nums[i] === nums[i - 1]) {
          continue;
        }
        // 剪枝：最小数已大于 0，后面不可能凑出 0
        if (nums[i] > 0) {
          break;
        }

        let left = i + 1;
        let right = n - 1;
        const target = -nums[i];

        while (left < right) {
          const currentSum = nums[left] + nums[right];
          if (currentSum === target) {
            result.push([nums[i], nums[left], nums[right]]);
            // 跳过相同的第二个数和第三个数
            while (left < right && nums[left] === nums[left + 1]) {
              left++;
            }
            while (left < right && nums[right] === nums[right - 1]) {
              right--;
            }
            // 双指针同时内移
            left++;
            right--;
          } else if (currentSum < target) {
            left++;
          } else {
            right--;
          }
        }
      }

      return result;
    }

    // 测试用例
    console.log(threeSum([-1, 0, 1, 2, -1, -4])); // [[-1, -1, 2], [-1, 0, 1]]
    console.log(threeSum([0, 1, 1])); // []
    console.log(threeSum([0, 0, 0])); // [[0, 0, 0]]

## Python 与 TypeScript 差异点评

双指针框架一致，最易错的是排序写法：

<CodeCompare
  py={`# 默认按数值排序
nums.sort()`}
  ts={`// 必须传比较函数，否则按字典序
nums.sort((a, b) => a - b);`}
/>

| 关注点   | Python                       | TypeScript                                  |
| -------- | ---------------------------- | ------------------------------------------- |
| 排序     | `nums.sort()` 即数值排序     | `sort((a, b) => a - b)`，无参数按字符串排序 |
| 去重比较 | `nums[i] == nums[i - 1]`     | `nums[i] === nums[i - 1]`，严格相等         |
| 结果收集 | `result.append([...])`       | `result.push([...])`                        |
| 循环边界 | `range(n - 2)`               | `i < n - 2`，语义一致                       |
| 变量声明 | `left, right = i + 1, n - 1` | `let left` / `let right`，需可变绑定        |
| 输出测试 | `print(...)`                 | `console.log(...)`                          |

:::note
JS 无比较函数的 `sort` 会把 `[-4, -1, 2]` 排成错误顺序，双指针移动规律全失效。从 Python 迁移时务必把比较函数当作固定搭配。
:::

## 常见错误分析

### 1. 忘记排序直接双指针

```python
# 错误：无序数组上移动指针毫无依据
for i in range(n - 2):
    left, right = i + 1, n - 1
```

双指针依赖有序性：和太小需要右边更大，和太大需要左边更小。**改法**：函数首行先 `nums.sort()`，去重与剪枝同样依赖有序。

### 2. 命中后只移动一个指针

```python
# 错误：left 与 right 原地不动，循环永不推进
if current_sum == target:
    result.append([nums[i], nums[left], nums[right]])
    left += 1  # 忘记 right -= 1，且未跳过重复
```

同一组合被反复命中，轻则重复答案，重则死循环。**改法**：先用两个 `while` 跳过重复值，再 `left += 1; right -= 1` 同时内移。

### 3. TypeScript 里排序与比较连环坑

```typescript
// 错误：字典序排序 + 宽松比较
nums.sort();
if (nums[i] == nums[i - 1]) continue;
```

`[10, 2]` 会被排成 `[10, 2]`，`10 < 2` 按字符串成立。**改法**：排序必带 `(a, b) => a - b`，比较用 `===`。strict 模式不会拦截逻辑错误的排序，只能靠固定写法避免。Python 侧无此坑，但 `range(n - 1)` 配 `left = i` 会复用同一元素，需保持 `range(n - 2)` 与 `left = i + 1` 配套。

## 面试变体

1. **有序两数之和**：排序已成立时双指针 O(n)、O(1)，是本题内层退化形态（详见[两数之和](../two-sum/)）。对比点在于无序版需哈希表，有序版可用指针。
2. **最接近的三数之和**：同样固定加双指针，但维护 `closest` 而非收集答案，无需三处去重。时间 O(n²)、空间 O(1)，命中不等时按差值更新。
3. **四数之和**：再固定一个数，双指针找剩余两数，总复杂度 O(n³)。去重从三处变为四处，剪枝条件相应放宽。

## 面试追问

- 为什么必须先排序？（双指针移动、相邻去重、`nums[i] > 0` 剪枝三者都依赖有序，答案要点是把无序查找变为有序逼近。）
- 三处去重分别防什么？（外层防相同起点重复整组，内层两处防同一起点下重复收集。）
- 时间为何是 O(n²)？（外层 n 次，内层指针最多走 O(n) 步，排序 O(n log n) 被主导。）
- 能否优化到 O(n)？（公认下界为 O(n²)，目前无更好一般解法。）

**三个 Bug：**

**Bug 1：** `i > 1` 应该是 `i > 0`

- `i > 1` 会漏掉第二个元素的去重检查

- 没有这两行代码，`left` 和 `right` 不会移动，会陷入死循环
