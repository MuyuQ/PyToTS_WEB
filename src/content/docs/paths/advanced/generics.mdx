## 场景与问题

泛型允许编写可重用的、类型安全的代码。Python 3.12+ 支持泛型，但 TypeScript 的泛型系统更强大。

## Python 回顾

```python
from typing import TypeVar, Generic, List

T = TypeVar('T')

# 泛型函数
def first(items: List[T]) -> T:
    return items[0]

# 泛型类
class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: List[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

# 使用
stack = Stack[int]()
stack.push(1)
stack.push(2)
print(stack.pop())  # 2
```

## TypeScript 等价写法

```typescript
// 泛型函数
function first<T>(items: T[]): T {
  return items[0];
}

// 泛型类
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T {
    return this.items.pop()!;
  }

  // 查看栈顶元素但不弹出
  peek(): T | undefined {
    return this.items[this.items.length - 1];
  }
}

// 使用
const stack = new Stack<number>();
stack.push(1);
stack.push(2);
console.log(stack.pop()); // 2

// 类型推断 - 不需要显式指定
const stack2 = new Stack<string>();
stack2.push("hello");
```

## 差异与常见陷阱

### 1. 泛型约束

```typescript
// 要求 T 必须有 length 属性
function logLength<T extends { length: number }>(arg: T): T {
  console.log(arg.length);
  return arg;
}

// 可以使用
logLength("hello"); // ✓ 字符串有 length
logLength([1, 2, 3]); // ✓ 数组有 length
logLength({ length: 10 }); // ✓ 对象有 length

// 错误
// logLength(123);         // ✗ number 没有 length
```

### 2. 多泛型参数

```typescript
// 键值对映射
function mapToArray<K, V>(map: Map<K, V>): [K, V][] {
  return Array.from(map.entries());
}

// 使用
const userMap = new Map<string, number>();
userMap.set("Alice", 25);
userMap.set("Bob", 30);

const pairs = mapToArray(userMap);
// pairs: [string, number][]
```

### 3. 默认泛型参数

```typescript
// 可以设置默认值
interface Container<T = string> {
  value: T;
}

const c1: Container = { value: "hello" }; // T 默认为 string
const c2: Container<number> = { value: 42 }; // T 显式指定为 number
```

### 4. 条件类型（TypeScript 特有）

```typescript
// 根据类型选择不同结果
type IsString<T> = T extends string ? true : false;

type A = IsString<string>; // true
type B = IsString<number>; // false

// 实际应用：提取 Promise 返回值
type UnwrapPromise<T> = T extends Promise<infer R> ? R : T;

type C = UnwrapPromise<Promise<number>>; // number
type D = UnwrapPromise<string>; // string
```

## 优势对比

| 特性     | Python                    | TypeScript |
| -------- | ------------------------- | ---------- |
| 语法     | `TypeVar('T')`            | `<T>`      |
| 约束     | `TypeVar('T', bound=...)` | `extends`  |
| 默认参数 | 不支持                    | 支持       |
| 条件类型 | 不支持                    | 支持       |
| 类型推断 | 有限                      | 强大       |

## 试试看

### 预测输出

下面代码会输出什么？先想想泛型参数 `T` 在运行时还在不在，再看答案。

```typescript
function identify<T>(value: T): T {
  return value;
}

console.log(typeof identify(42), typeof identify("ts"));
```

<details>
<summary>点击查看答案</summary>

输出：`number string`。

`T` 由实参推断：传 `42` 时是 `number`，传 `"ts"` 时是 `string`，编译器据此检查返回值；但编译成 JavaScript 后泛型信息被擦除，`identify` 只是原样返回参数的函数。`typeof` 看到的是运行时真正的值，不是 `T` 这个类型变量。

**Python 里会怎样、为什么会想错**：Python 的 `TypeVar` 同样只服务于静态检查，运行时 `type(x)` 拿到的也是真实类型；但 `T` 写得像个变量，容易误以为能在运行时判断它、或对它调用方法。泛型是写给编译器的约束，不是运行时对象。

</details>

### 找错误

下面代码有一个错误，能找到吗？

```typescript
function shout<T>(value: T): string {
  return value.upper(); // 想调用 Python 熟悉的字符串方法
}

console.log(shout("hello"));
```

<details>
<summary>点击查看答案</summary>

错误在 `value.upper()`：对未约束的 `T`，编译器只知道「某种类型」，不知道它有 `upper` 方法，会报 `Property 'upper' does not exist on type 'T'`。即便调用时只传字符串也一样——声明要对**所有**可能的 `T` 成立。

两种改法：

```typescript
// 1. 用 extends 明确约束 T 必须具备该方法
function shout<T extends { upper(): string }>(value: T): string {
  return value.upper();
}

// 2. 本来只处理字符串，就别用泛型
function shout(value: string): string {
  return value.toUpperCase();
}
```

顺带一个差异：TypeScript 的字符串方法叫 `toUpperCase()`，不是 Python 的 `upper()`。

**Python 里会怎样、为什么会想错**：Python 靠鸭子类型，函数体里 `value.upper()` 想写就写，传进来的对象有没有这个方法要等运行才知道；TypeScript 要求在声明时就把「允许调用什么」写进约束。本课的 `extends { length: number }` 就是同一招。

</details>

## 练习

将以下 Python 代码转换为 TypeScript：

```python
from typing import TypeVar, Generic, Dict, Optional

T = TypeVar('T')
K = TypeVar('K')
V = TypeVar('V')

class Cache(Generic[K, V]):
    def __init__(self):
        self._data: Dict[K, V] = {}

    def set(self, key: K, value: V) -> None:
        self._data[key] = value

    def get(self, key: K) -> Optional[V]:
        return self._data.get(key)

    def has(self, key: K) -> bool:
        return key in self._data

# 使用
cache = Cache[str, int]()
cache.set("score", 100)
print(cache.get("score"))  # 100
```

<details>
<summary>答案</summary>

```typescript
class Cache<K, V> {
  private data = new Map<K, V>();

  set(key: K, value: V): void {
    this.data.set(key, value);
  }

  get(key: K): V | undefined {
    return this.data.get(key);
  }

  has(key: K): boolean {
    return this.data.has(key);
  }
}

// 使用
const cache = new Cache<string, number>();
cache.set("score", 100);
console.log(cache.get("score")); // 100
```

**为什么这么写**：`Dict[K, V]` 对应 `Map<K, V>`，键值都保留为泛型参数，同一份实现才能服务不同 `Cache` 实例。`Optional[V]` 在 TypeScript 里写成 `V | undefined`，因为 `Map.get` 找不到键时返回 `undefined` 而不是 `None`；判断存在性要用 `Map.has`，`in` 是检查对象属性的运算符，不能用在 `Map` 上。

</details>

## 自测清单

- 能写出泛型函数与泛型类，并说明 `T` 如何由实参推断
- 能用 `extends` 给类型参数加约束，并解释未约束的 `T` 为什么不能访问属性
- 能区分泛型约束与运行时类型检查，说明编译后 `T` 去了哪里
- 能写条件类型并用 `infer` 提取 `Promise` 的返回值类型
- 能对比 Python `TypeVar`/`Generic` 与 TypeScript 泛型，指出「编译期擦除」的含义
- 能判断什么时候不该用泛型（只处理一种类型时属于多余抽象）

## 面试追问

1. **什么时候应该使用泛型？**
   - 答：当函数或类需要处理多种类型，但又要保持类型安全时。

2. **`extends` 和 `implements` 在泛型中的区别？**
   - 答：`extends` 用于约束泛型参数必须满足某些条件，`implements` 用于类实现接口。
